# Goal prompt — 에피소드 전체 파이프라인 완성

아래 프롬프트를 새 에피소드의 `goal` objective로 사용한다. `{EPISODE_ID}`와
`{EPISODE_JSON}`만 바꾼다.

```text
유튜브 쇼츠 자동화 프로젝트의 {EPISODE_ID} 에피소드를 저장소에서 실제 재현 가능한
상태까지 완성하라. 기준 episode는 {EPISODE_JSON}이다.

완료 기준:

1. 에피소드가 12-18개 장면이고, 실제 TTS 기준 총 길이가 50-70초인지 검증한다.
2. 미디어 후보를 장면별로 수집하고, 원본 URL·landing URL·제작자·라이선스·출처 표기와
   사람 검토 상태를 유지한다. 라이선스 승인과 게시 여부를 자동 확정하지 않는다.
3. 대본 문맥과 후보 수를 바탕으로 `full_frame`, `split_2up_left_right`,
   `split_2up_top_bottom`, `sequence` 중 연출을 추천한다. 추천 레이아웃, 후보 ID,
   표시 순서, confidence, reason을 manifest에 기록하고 사람이 override할 수 있게 한다.
   기존 `split_2up`은 좌우 레이아웃 alias로 유지한다.
4. `sequence` 장면은 `fade`, `slide_left`, `slide_up`, `cut` 전환을 지원한다.
   기본값은 과도하게 화려하지 않게 하고 같은 효과가 연속 반복되지 않게 한다.
5. 나무위키를 사용할 때 표 정보는 제목·헤더·관련 행을 포함한 표 전체를, 설명 정보는
   문단 또는 목록 항목 전체를 캡처한다. 모바일 화면에서 읽을 수 있게 하고, 표·문단은
   영상에서 전체 맥락이 잘리지 않도록 배치한다. 캡처 시 URL·history URL·시각·match·
   context·제3자 미디어 포함 여부를 기록한다.
6. 사용자가 승인하기 전에는 생성 이미지를 만들지 않는다. 후보 부족 장면은 추가 검색
   또는 텍스트 카드 대기 상태로 남긴다.
7. 프로젝트 TTS 정책에 따라 Supertonic 3 F1을 기본으로 사용한다. 각 WAV의 샘플레이트,
   길이, finite 값, 무음·상수 신호, peak/RMS를 검증한다. Qwen GPU 비교는 다시 열지 않는다.
8. 실제 TTS 길이로 자막 타이밍을 만들고, 캡션 안전영역을 지키는 1080x1920 MP4를 만든다.
   시작 장면에는 알아볼 수 있는 AI 음성 고지를 포함한다.
9. 정상 경로뿐 아니라 후보 부족, 상하 split, sequence 전환, 연속 전환 반복 방지,
   무음 WAV, 잘못된 이미지, 50초 미만·70초 초과 영상, 미승인 자산의 final render
   차단을 테스트한다.
10. README.md, AGENTS.md, HISTORY.md, 관련 references와 스킬 문서를 갱신한다.
    WSL 실행 명령을 문서에 남긴다.
11. YouTube 로그인·업로드·공개 게시와 법률적 라이선스 판단은 범위 밖으로 둔다.
12. 검증이 끝나면 의도한 파일만 커밋하고 현재 브랜치에 push한다.

작업 완료 후 다음 순서로 보고하라:

- 구현한 항목
- 실행한 명령과 통과/실패 테스트
- 생성된 결과물과 검토 리포트
- 아직 사람의 결정이 필요한 항목(후보 선택, 라이선스, 사실 검수, 게시 여부)
- 사람과 항목별 리뷰를 진행하기 위한 번호 목록
```

실행 중에는 후보를 자동으로 `approved`로 변경하지 말고, 사람이 검토해야 하는 지점을
명시적으로 남긴다. `--draft` 결과는 검토용이며 최종 게시물로 간주하지 않는다.
